# evocode

> **Язык:** [English](README.md) · Русский — как добавить язык, см. [TRANSLATING.md](TRANSLATING.md).

Чтение, декодирование, подпись и запись **кодировки** головного устройства BMW **NBT EVO** по
ENET/HSFZ — маленькая Python-библиотека и CLI без зависимостей.

> 🤖 **Управляется ИИ-агентом или техническим оператором у машины — это не самообслуживаемое
> потребительское приложение.** Каждая команда предполагает того, кто умеет прочитать UDS
> negative-response, подключить ENET и оценить, как изменение повело себя на устройстве. Начните с
> **[AGENTS.md](AGENTS.ru.md)**: модель работы, две плоскости доступа (почему кодировке и FSC **не
> нужен SSH**) и карта рисков.

> **Область: только NBT EVO (QNX)** — iDrive **ID4 / ID5 / ID6**. Это **не** для MGU / **ID7+**
> (BMW OS 7/8, Linux); это другое головное устройство и другая платформа. См.
> [docs/scope.md](docs/scope.ru.md).

> ⚠️ **Запись кодировки может «окирпичить» или ухудшить работу головного устройства.** Чтение
> безопасно; запись защищена воротами, по умолчанию идёт «вхолостую» (dry-run) и отказывается
> работать, пока VIN подключённой машины не совпадёт с вашим. Всегда делайте бэкап, проверяйте
> офлайн и держите бэкап как откат. Только на своей машине.

## Статус

Версия 0.2.x, ядро на чистом stdlib, на PyPI (`pip install evocode`). Что доказано, а что нет:

- **Кодировка (диагностическая плоскость) — доказана на реальных данных.** Транспорт HSFZ, подпись
  `BMWSigVerify`, `read`/`decode`/`verify`/`sign`/`write`. Подписчик воспроизводит собственную подпись NCD
  реальной машины **байт-в-байт** ([examples/a4a.md](examples/a4a.ru.md)); `write` — **по умолчанию
  dry-run**, с воротами по VIN. `recover-key` восстанавливает ваш ключ NCD/L3 из вашей же PSdZData (точно);
  `build-catalog` расшифровывает ваш `.caf` → полный скелет координат (1469 для CAFD `00001EF6`;
  A4A/CarPlay подтверждены), имена — слой сообщества. (`recover-key`/`build-catalog` — extra `crypto` + `openssl`.)
- **FSC-активации, owner-CA (`fsc …`) — крипта доказана офлайн; on-car путь ещё не на живом юните.**
  `keygen`/`mint`/`verify`/`whosigned`/`fingerprint`/`from-log`/`find-blobb`/`patch-blobb` доказаны на
  реальных якорях и FSC офлайн. On-car `apply`/`read`/`disable` (SwtRoutine `0x0F1F`; store `0x07` = SWID +
  сырой FSC, read `0x0B`, disable `0x0A`) выведен из ODX BMW F020 — **ещё не проверен на живом юните**;
  dry-run по умолчанию, ворота по VIN.
- **Root / OPT_DEBUG (`root …`) — реализован, ещё не на живом юните.** Поднимает dev-SSH диагностическим
  SWDL-флешем (`swdl.py`): version-matched `starter.cfg`, dry-run, обратимо.
- **Установка прошивки (`fw …`, опциональный extra `[ssh]`) — хореография проверена на живом эмуляторе
  QNX 6.5.** Безопасная замена файла по dev-SSH (бэкап → upload → **сверка размера** → rename-over →
  рестарт). Последовательность команд идёт на живом QNX; сам SSH-транспорт **ещё не проверен на реальной
  машине**. См. [docs/testing.md](docs/testing.ru.md).

## Установка

```bash
pip install -e .          # чистый stdlib; без рантайм-зависимостей
```

## Быстрый старт

```bash
export NBTEVO_OWN_VIN=<ваш VIN>      # VIN машины, которой вы владеете

# 1. Идентифицировать устройство (читает SVK: BTLD + CAFD + VIN). Никогда не предполагать их.
evocode identify --host 169.254.199.99

# 2. Сделать бэкап живой кодировки в NCD (делать каждый раз — это и есть откат).
evocode read --host 169.254.199.99 -o backup.ncd

# Посмотреть, что говорит текущая кодировка, против каталога.
evocode decode --ncd backup.ncd --catalog catalogs/cafd_00001ef6.json

# 3. Восстановить ВАШ ключ подписи кодировки из ВАШЕЙ PSdZData (один раз), затем доказать, что
#    подписчик воспроизводит собственную подпись машины байт-в-байт.
evocode recover-key --btld 00001FFD --psdzdata /path/to/psdzdata -o key.json
evocode verify --ncd backup.ncd --key key.json

# 4. Поменять байт кодировки и переподписать офлайн (локальная проверка до отправки на машину).
evocode sign backup.ncd modified.ncd --key key.json --set 0x3000,107,1,0x80,7

# 5. Записать (DRY RUN, пока нет --commit; --commit заново сверяет VIN и подпись).
evocode write --host 169.254.199.99 --ncd modified.ncd --key key.json --l3-key l3.json --commit

# 6. Подтвердить: прочитать обратно и сравнить, посмотреть, как поднимается HMI. Откат = запись backup.ncd.
evocode read --host 169.254.199.99 -o after.ncd
```

## Как это работает (один абзац)

NBT EVO заново проверяет криптографическую подпись над своей кодировкой **при каждой загрузке**.
Сырая правка байта откатится, если не пересчитать подпись ключом, который выбирает загрузчик (BTLD).
Поэтому долговечное изменение — это: поправить датагруппы, пересчитать подпись `BMWSigVerify` (MD5,
RSA `e=3`, фирменная BMW кодировка big-number с перестановкой слов, хранится в датагруппе `0x3010`),
затем записать обе через аутентифицированную UDS-сессию кодировки (SecurityAccess L3, `2E` по каждой
датагруппе, подпись последней, `CheckCodingSignature`, CPS, сброс). Математика — в
[`evocode/coding.py`](evocode/coding.py); проводной поток — в [docs/protocol.md](docs/protocol.ru.md).

## Каталоги — как сырая координата становится читаемым параметром

`0x3000,107,bit7` не значит ничего, пока **каталог** не скажет, что это `A4A` на вашей CAFD. Каталоги —
это карты по CAFD, собранные из **вашей собственной** PSdZData через `evocode build-catalog` (см.
[catalogs/README.md](catalogs/README.ru.md)). Это держит провенанс чистым и позволяет сообществу
добавлять устройства вкладом каталогов, а не кода — один и тот же код обслуживает любую сборку NBT
EVO. Чтобы добавить или назвать параметр, следуйте
**[catalogs/CONTRIBUTING.md](catalogs/CONTRIBUTING.ru.md)** (для людей и агентов).

## Активации FSC (owner-CA)

Отдельная от кодировки возможность: FSC (CarPlay, навигация, A4A…) проверяется против одного модуля
(**blobB**) в прошивке (`e=3`/MD5), а не против ключа кодировки BMW. На своей машине можно перенести
это доверие на **свой** ключ и минтить FSC под ним:

```bash
evocode fsc keygen -o owner.json --blobb owner_blobB.bin           # ваш якорь e=3
evocode fsc find-blobb NBTCarHU                                    # найти установленный якорь + отпечаток
evocode fsc whosigned --fsc a.fsc --fsc b.fsc --recover           # чей якорь на б/у устройстве?
evocode fsc patch-blobb NBTCarHU --key owner.json --backup stock_blobB.bin -o NBTCarHU.patched
evocode fsc mint --key owner.json --appno 0x0143 -o carplay.fsc   # CarPlay (VIN-generic)
evocode fsc apply --fsc-dir ./fscs                                # dry-run; добавьте --host/--l3-key/--commit для записи
evocode fsc read  --host 169.254.199.99 --appno 0x0143            # прочитать текущий статус FSC (безопасно, без SecurityAccess)
evocode fsc disable --host 169.254.199.99 --appno 0x0143          # dry-run; добавьте --l3-key/--commit чтобы отключить
```

`verify` / `parse` / `fingerprint` / `from-log` дополняют картину. Установка пропатченного `NBTCarHU` —
шаг замены прошивки (риск «кирпича»): сохраните сток-якорь (`--backup`), держите его для отката и
сначала отрепетируйте своп в эмуляторе — см. [docs/testing.md](docs/testing.ru.md). evocode умеет и сам
установить файл по SSH — `evocode fw install` (опциональный extra `[ssh]`): бэкап + rename-over новым
inode, dry-run по умолчанию (`fw pull` снимет живой бинарь для патча, `fw revert` вернёт стоковый).
Этот шаг требует root-шелла на устройстве — см. **[docs/root-access.md](docs/root-access.ru.md)**: как
включается root/SSH (OPT_DEBUG), почему это ENET-флеш, а не SSH-операция сама по себе, и его риски.
