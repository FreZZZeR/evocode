# Каталоги — карты битов по CAFD

> **Язык:** [English](README.md) · Русский

**Добавляете или называете параметр?** См. **[CONTRIBUTING.md](CONTRIBUTING.ru.md)** (люди и агенты).

**Каталог** превращает сырую координату кодировки (`datagroup, byte, mask, shift`) в осмысленное для
человека имя параметра и набор значений — для одной **CAFD** (набора данных кодировки). Код одинаков
для любого NBT EVO; новая машина поддерживается добавлением каталога, а не изменением кода.

## Провенанс

Каталоги выводятся из **вашей собственной** PSdZData через `evocode build-catalog`. Проект не
поставляет ни одного каталога, предвыведенного из чужих данных, — это держит провенанс данных таким же
чистым, как у кода (см. [../CREDITS.md](../CREDITS.md)). Если вы вносите каталог, генерируйте его из
своих лицензионных референс-файлов и указывайте, из какого id и версии CAFD он получен.

## Формат (черновик)

Один JSON-файл на CAFD, `cafd_<id>.json`:

```json
{
  "cafd": "00001EF6",
  "version": "006.031.014",
  "parameters": [
    {
      "name": "A4A",
      "datagroup": "0x3000",
      "byte": 107,
      "mask": "0x80",
      "shift": 7,
      "values": { "0": "nicht_aktiv", "1": "aktiv" }
    }
  ]
}
```

- `datagroup`/`byte`/`mask`/`shift` адресуют ровно то, что правит `evocode sign --set`.
- `values` сопоставляет декодированное целое с меткой.
- Читатель (`evocode decode`) применяет каталог к прочитанному NCD и печатает текущие значения;
  подписчик и так принимает те же координаты напрямую.

## Статус

`decode` и `build-catalog` реализованы. `evocode build-catalog --caf <ваш .caf> …` расшифровывает
вашу собственную CAFD (CMS + gzip, ключом Codier-Encrypt из вашего keystore) и пишет **полный
скелет** — каждую координату, mask и default (1469 для CAFD `00001EF6`). **Имена** параметров — это
то, что вы добавляете сверху: BMW поставляет CAFD с вырезанными именами, поэтому они приходят из
firmware-токенов / авторства сообщества. Ядру read / sign / write каталог не нужен — координаты можно
адресовать и напрямую.
