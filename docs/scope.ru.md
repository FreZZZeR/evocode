# Область — какие головные устройства покрыты (а какие нет)

> **Язык:** [English](scope.md) · Русский

Библиотека нацелена на головное устройство **NBT EVO**: **QNX**-основанный iDrive-компьютер, который
применялся в BMW серий F и ранних G и ведёт поколения UI **ID4 / ID5 / ID6**. Всё здесь — транспорт
HSFZ, UDS-поток кодировки, подпись кодировки `BMWSigVerify`, раскладка датагрупп — специфично для этой
платформы.

## Лестница поколений

| Головное устройство | ОС | Поколение UI | Эта библиотека |
|---|---|---|---|
| CIC | QNX | — | нет |
| NBT | QNX | ID4 | частично (та же семья; проверять по устройству) |
| **NBT EVO** | **QNX** | **ID5 / ID6** | **да — цель** |
| MGU (Media Graphics Unit) | **Linux** | **ID7 / ID8** (BMW OS 7/8) | **нет — другая платформа** |

## Почему ID7 / MGU вне области

ID7 — это не новая оболочка на том же компьютере, это другое головное устройство (**MGU**) на
**Linux**-основанной ОС (BMW Operating System 7, позже 8). Его модель кодировки, его схема
подписи/доверия, его диагностические сервисы и его файловая система — все отличаются от QNX-мира NBT
EVO. Ни один из примитивов отсюда не переносится. Поддержка MGU была бы отдельным проектом, а не
добавлением каталога.

## Что *переносится* внутри NBT EVO

**Механизм** постоянен для сборок NBT EVO — математика подписи кодировки, хореография записи,
транспорт. Что меняется от устройства к устройству — это **данные**: id загрузчика (BTLD), который
выбирает ключ подписи, и карта по **CAFD** — какие биты что значат. Поэтому код пишется один раз;
поддержка новой машины — это новый **каталог** (см. [../catalogs/](../catalogs/)), а не новый код.

Всегда сначала читайте **SVK** устройства (`22 F1 01`) и опирайтесь на реальные id BTLD + CAFD —
никогда не предполагайте их по модельному году.
