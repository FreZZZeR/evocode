# Протокол — кодировка NBT EVO «по проводу»

> **Язык:** [English](protocol.md) · Русский

Это механизм, который реализует код. Это собственный протокол BMW, здесь пере-выраженный; см.
[../CREDITS.md](../CREDITS.md).

## Транспорт — HSFZ

Машины F/ранних G говорят на **HSFZ** по TCP **6801** (не DoIP). Кадр —
`u32 payload_len | u16 control | u8 source | u8 target | UDS…`, где `payload_len` считает байты после
control-слова. control `0x0001` — данные, `0x0002` — ack, который пропускаем. Эндпоинты отвечают на
UDP-broadcast `0x0011` на 6811. Маршрутизация — по байту **target**: `0xF4` тестер, `0x10` шлюз,
`0x63` головное устройство NBT EVO. (`evocode/hsfz.py`)

## Идентичность — SVK

Прочитайте `22 F1 01` и декодируйте (`evocode/uds.py`): он перечисляет каждый программный блок как
8-байтовый SGBM id (класс, id, версия). **BTLD** (загрузчик) выбирает ключ подписи кодировки;
**CAFD** (набор данных кодировки) выбирает раскладку битов. Всё опирается на эти два — никогда их не
предполагайте.

## Подпись кодировки — BMWSigVerify

Кодировка живёт в **датагруппах** `0x3000…0x300F`; **подпись** — это датагруппа `0x3010`. Головное
устройство заново проверяет подпись при каждой загрузке, поэтому долговечная правка должна её
пересчитать (`evocode/coding.py`):

1. `digest = MD5( конкатенация датагрупп 0x3000…0x300F )`.
2. `s = (int(digest, little))^d mod N` — сырое RSA с восстановленным приватным экспонентом, `e = 3`.
3. записать `wordswap(s)` (каждое 32-битное слово байт-реверснуто) в `0x3010`, с префиксом big-endian
   32-битного счётчика слов.

Проверка прогоняет это вперёд с публичным модулем. Верификатору нужен только модуль; подписи нужен
приватный экспонент, восстановленный из вашей собственной PSdZData.

## Долговечная запись — UDS-хореография

```
10 03                 extendedDiagnosticSession
10 41                 codingSession
27 01 -> seed         SecurityAccess requestSeed (level 01)
27 02 <key>           sendKey = L3-рукопожатие над seed (evocode/l3.py)
2E 30 00 <bytes>      записать каждую изменённую датагруппу …
2E 30 10 <sig>        … датагруппу подписи ПОСЛЕДНЕЙ
31 01 0F 01           CheckCodingSignature — должна пройти, иначе прервать до CPS
2E 37 FE <cps>        Coding Production Stamp
11 01                 жёсткий сброс; HU перезагружается и заново проверяет
```

SecurityAccess здесь — общая конструкция **L3** (тот же ключ открывает флеш на уровне 11):
`MD5([UserID][Controller][seed])`, подписанный сырым RSA `e=3` little-endian, с префиксом счётчика
слов + перестановкой слов подписи.

## Откат

Прочитанный бэкап уже корректно подписан (его произвела машина). Запись его обратно — чистый откат.
`evocode write` по умолчанию идёт вхолостую, сначала проверяет подпись локально, а на `--commit`
отказывается, пока VIN подключённой машины не совпадёт с `NBTEVO_OWN_VIN`.
